Seventh release candidate for Linux x86_64: every tool connects the same way, project memory,
and a crew you can set and see.

**Before you upgrade:** Claude Code and Codex now sign in for GovernCode with their own sign-in,
in a home that belongs to GovernCode, instead of using your own login. After upgrading, connect
them once: `gov connect claude` and `gov connect codex`, or Settings › Tools in the Dashboard.
Until then a Controller turn says so and does not start.

## Added

- **Connect for Claude Code and Codex**, as for Antigravity. Claude Code shows a link and you
  paste back the code; Codex's page finishes the sign-in by itself. Only a subscription sign-in
  counts, never an API key. Your own setup for these tools is not used, except the personal
  instructions you choose to bring. `gov disconnect TOOL` removes GovernCode's copy of a login.
- **A fresh home for every Claude Code and Codex run**, with only its login linked in, deleted
  afterwards: nothing a run writes (memory, caches, settings, rules, skills) reaches another run.
- **Project memory.** Each turn gets the project's notes (kept by the Controller with a new
  `project_notes` tool; `gov notes`, or the Dashboard's Notes view, to read, edit and restore a
  version: every version is kept, the terminal restores any of the last 1,000 and the Dashboard
  lists the latest 50), the project's record from the Trace (recent Specs, Checkpoints, what you allowed) and
  the recent conversation. Switching a project to a Controller from another provider shows what
  would be shared and asks once.
- **The Crew card** (`gov crew`, or the Dashboard's Crew view): whether the Controller works
  itself or only plans and hands off (then the project is read-only for it), how handoffs are
  approved (ask each time, follow the approved plan, or off), which Runners and the most one job
  may reserve, and subagents on or off for the Controller and for Runners.
- **The game plan**: before bigger work the Controller is asked to post who does what (it is not
  forced to); you approve all or some items, answer "just you", or reject it. With "follow the
  approved plan", each approved item lets one handoff to that Runner through without asking again
  (the Runner is matched, not the item's wording).
- **The Crew board**, in the Crew view: the Controller, the subagents Claude Code starts, each
  job with its Runner's latest step, and the Gates waiting. (Codex's subagents are not shown yet.)

## Changed

- Every handoff and every discarded Spec is decided by govd itself, however the Controller
  reaches it; Claude Code and Codex no longer ask for those tools on their own.
- A Controller's Runners stop when its turn ends, and a finished turn opens no new Gate.
- Starting another AI coding tool from a command (`claude`, `codex`, `agy`, `gemini`, `ollama`...)
  always asks.
- The sandbox may let a tool listen on a local port only where GovernCode says so: none for any AI
  work, one for Claude Code's and Codex's sign-ins (the browser hands the login back through it).
- A turn cut off by govd stopping is closed on the record when govd starts again.
- A Codex Controller no longer opens a Gate to list Runners or read a Spec's status.

## Upgrading

Run `./install.sh` from this release (with `--service` if you used it before), restart govd
(`systemctl --user restart governcode`), then connect Claude Code and Codex once
(`gov connect claude`, `gov connect codex`, or Settings › Tools). Antigravity stays connected.
