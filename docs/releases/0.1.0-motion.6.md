Sixth release candidate for Linux x86_64: Antigravity as a Runner, a Connect step for tools, and
an uninstaller.

## Added

- **Antigravity (Google's `agy` CLI) as a Runner.** Every tool call it makes passes GovernCode's
  Gate through Antigravity's pre-tool hook: plain reads run, commands get the same checks as any
  other command, file changes show exactly what will be written, and any other tool follows your
  Gate level like any other kind of step. Its Limit comes from
  Antigravity's own usage report (weekly and 5-hour). Gemini models (or Antigravity's default)
  only for now.
- **Connect.** `gov connect` lists the tools GovernCode can connect and checks each one;
  `gov connect agy` (or Settings › Tools › Connect in the Dashboard) runs the tool's own sign-in
  inside the sandbox, in a home that belongs to GovernCode, and `gov disconnect agy` removes it.
  Your own setup, keyring and settings are not used, and GovernCode never reads the login the tool
  keeps there. Connect needs `script` (util-linux) for the sign-in's terminal. Claude Code and
  Codex keep using your own logins in this release.
- **`./install.sh --uninstall [--purge]`** removes the `governcode.service` user service, the
  `gov`, `govd` and `governcode-dashboard` links, the launcher entry and every installed release.
  It removes only what it can show is GovernCode's: releases carry a mark written at install,
  links and the launcher entry must point exactly into one of them, and a process still running
  from the install (found by its command line, working folder or program) stops it before
  anything is removed. `--purge` also removes the Dashboard's settings and a state folder govd
  created itself (never one with a `.git` folder at its top). It does not touch your project
  folders.

## Changed

- A project containing Antigravity customization folders (`.agents/`, `.agent/`, `_agents/`,
  `_agent/`) is refused for an Antigravity Spec, and a Runner that creates one fails its Spec:
  their hooks could switch GovernCode's Gate off.
- `install.sh` installs only into a new folder, one it installed, or an older install of the same
  release, and refuses any other existing folder. It writes the systemd unit under
  `$XDG_CONFIG_HOME` when that is set.
- The sockets govd opens for a turn ignore anything that is not a JSON request object and close a
  connection that sends a message over 1 MB.

## Upgrading

Run `./install.sh` from this release (with `--service` if you used it before), then restart
govd: `systemctl --user restart governcode`, or stop and start `govd`. To use Antigravity as a
Runner, connect it once with `gov connect agy` or in Settings › Tools. Releases installed by
earlier versions of `install.sh` carry no mark, so `--uninstall` lists them and leaves them for
you to remove; the same goes for a state folder that existed before this release.
